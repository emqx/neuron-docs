# MQTT V2

MQTT V2 是按设备组织数据的 MQTT 北向插件。每个订阅的南向设备都有自己的一组 topic：

- 状态 topic：发布 retain 的设备状态消息，包含连接状态、运行状态和设备属性；
- 数据 topic：上报采集数据，格式由数据模板和点位模板决定；
- 写请求和写响应 topic：接收点位写入请求，并返回写入结果。

北向应用本身的在线状态也以 retain 消息发布，并注册了遗嘱消息。云端只需订阅 topic，就能拿到设备的最新状态、属性和数据。

MQTT V2 与 [MQTT](../mqtt/overview.md) 插件可以同时使用，MQTT 插件的行为不受影响。

| 对比项 | MQTT | MQTT V2 |
| --- | --- | --- |
| Topic | 在应用配置里填写写请求、写响应 topic，订阅时填写上报 topic | 由 topic 前缀和设备名自动生成，订阅时可为单个组改写数据 topic |
| 数据格式 | values-format、tags-format、ECP-format 或自定义格式 | 数据模板加点位模板，可使用内置变量 |
| 设备状态 | 定时上报所有南向驱动的状态 | 每个设备一条 retain 状态消息，变化时才发布 |
| 在线状态 | 无 | retain 在线状态消息，加遗嘱消息 |
| 设备属性 | 无，可用订阅的静态点位代替 | 支持，属性写入状态消息，模板中也能使用 |

::: tip
每个北向应用的 **客户端 ID** 必须唯一。客户端 ID 相同的连接会互相挤掉，broker 还可能发布遗嘱，把在线状态改成离线。
插件会订阅自身的在线状态 topic 和各设备的写请求 topic。在 MQTT Broker 上配置 ACL 时，请为这些 topic 授予订阅和发布权限。
:::

## 添加插件

在 **配置 -> 北向应用** 页面点击 **添加应用**，插件选择 **MQTT V2**。

## 应用配置

| 字段 | 说明 |
| --- | --- |
| **MQTT 版本** | MQTT 协议版本，可选 3.1.1 或 5.0，默认为 3.1.1。 |
| **客户端 ID** | MQTT 客户端 ID，必填，每个应用不可重复。默认值中的 `${random_str}` 在创建应用时会被替换为随机字符串。 |
| **QoS 等级** | 数据消息、写请求和写响应使用的 QoS，默认为 QoS 0。状态消息固定使用 QoS 1。 |
| **Topic 前缀** | 所有 topic 的前缀，默认为 `neuron/${app}`，`${app}` 会被替换为北向应用名称。只能使用 `${app}` 变量，不能包含 `+` 和 `#`。详见 [Topic 结构](#topic-结构)。 |
| **数据模板** | 数据消息的 JSON 模板，留空时使用默认模板。详见 [数据上下行格式](./api.md#数据上报)。 |
| **点位模板** | 数据模板中每个点位的 JSON 结构，留空时使用默认模板。模板里使用了 `${tag.error}` 时，读取失败的点位也会上报。详见 [数据上下行格式](./api.md#数据上报)。 |
| **服务器地址** | MQTT Broker 地址，必填。 |
| **服务器端口** | MQTT Broker 端口，必填。 |
| **用户名** | 连接 Broker 时使用的用户名，选填。 |
| **密码** | 连接 Broker 时使用的密码，选填。 |
| **SSL** | 是否启用 SSL，默认关闭。 |
| **CA 证书** | 启用 SSL 时必填。 |
| **客户端证书** | 使用 SSL 双向认证时填写。 |
| **客户端私钥** | 使用 SSL 双向认证时填写。 |
| **离线缓存** | 离线缓存开关，默认关闭。开启后，连接断开期间的数据消息会被缓存，重连后按顺序发送。状态消息不缓存，重连后会重新发布最新状态。 |
| **缓存内存大小（MB）** | 开启离线缓存时必填，范围 1–1024，不能大于缓存磁盘大小。 |
| **缓存磁盘大小（MB）** | 开启离线缓存时必填，范围 1–10240。 |
| **缓存消息重传间隔（MS）** | 开启离线缓存时必填，重连后每条缓存消息之间的发送间隔，范围 10–12000。 |

## Topic 结构

以默认前缀 `neuron/${app}` 为例，假设北向应用名为 `mqtt-v2`，南向设备名为 `modbus-1`：

| 用途 | Topic | 方向 | Retain |
| --- | --- | --- | --- |
| 北向在线状态 | `neuron/mqtt-v2/state` | 发布，插件同时订阅该 topic | 是 |
| 设备状态 | `neuron/mqtt-v2/modbus-1/state` | 发布 | 是 |
| 设备数据 | `neuron/mqtt-v2/modbus-1/data` | 发布 | 否 |
| 写请求 | `neuron/mqtt-v2/modbus-1/write/request` | 订阅 | — |
| 写响应 | `neuron/mqtt-v2/modbus-1/write/response` | 发布 | 否 |

- 设备第一次被订阅时，插件开始订阅它的写请求 topic；该设备的所有组都取消订阅后，插件停止订阅。
- 名称中的 `+` 和 `#` 在 topic 中会被替换为 `_`，消息内容中仍使用原名。
- 修改 Topic 前缀、北向应用名或南向设备名后，所有 topic 会随之更新，旧 topic 下的 retain 状态会被清除。

## 状态消息

状态消息的格式固定，不受模板影响，都是 retain 消息，QoS 为 1。

### 北向在线状态

- 连接 Broker 时注册遗嘱消息 `{"online": false}`。
- 连接成功后发布：

  ```json
  {"online": true, "timestamp": 1731744000123}
  ```

- 应用正常停止时，先发布 `{"online": false, "timestamp": ...}`，再断开连接，这种情况不会触发遗嘱。
- 运行期间如果该 topic 被改成离线状态，例如旧连接的遗嘱迟到，插件会重新发布在线状态。

### 设备状态

```json
{"timestamp": 1731744000123, "name": "modbus-1", "state": 1, "running": 3, "location": "Building A", "line": 3}
```

| 字段 | 说明 |
| --- | --- |
| `timestamp` | 发布时间，Unix 毫秒时间戳。 |
| `name` | 南向设备名称。 |
| `state` | 连接状态：0 断开，1 已连接。 |
| `running` | 运行状态：1 初始化，2 就绪，3 运行中，4 已停止。 |
| 其他字段 | 设备属性，详见 [设备属性](#设备属性)。 |

以下情况会发布设备状态：

- 连接或重连 Broker 后，发布全部已订阅设备的状态；
- 设备第一次被订阅；
- 设备的连接状态或运行状态变化，插件每秒检查一次；
- 设备属性变化。

以下情况会发布空的 retain 消息，清除该设备的状态：

- 该设备在本应用中订阅的所有组都已取消订阅；
- 南向设备被删除；
- 南向设备被重命名，此时清除旧名称下的状态，并在新名称下发布状态；
- 北向应用被删除，或 Topic 前缀被修改。

与 Broker 断开连接期间不发布状态消息，重连后会重新发布。

## 设备属性

设备属性是南向设备的静态 key/value 信息，例如位置、产线、资产编号。属性在南向设备上配置，订阅了该设备的所有 MQTT V2 应用都会使用。

可以通过 HTTP API 设置属性，例如：

```http
POST /api/v2/node/properties
```

```json
{
    "node": "modbus-1",
    "properties": [
        {"key": "location", "value": "Building A"},
        {"key": "line", "value": 3},
        {"key": "thresholds", "value": [0, 12.5]}
    ]
}
```

- **取值类型**：属性值可以是字符串、布尔、整数、浮点数，也可以是元素类型相同的一维数组。
- **接口操作**：该接口还支持 GET 查询、PUT 修改单个属性、DELETE 删除属性。
- **设备状态**：属性会自动平铺到设备状态消息中，属性增删改后状态消息会立即重新发布。`timestamp`、`name`、`state`、`running` 是固定字段，与它们同名的属性不会出现在状态消息中。
- **数据消息**：默认不带属性。如需带上，在数据模板或点位模板中使用 `${properties}` 或 `${properties[key]}`，详见 [数据上下行格式](./api.md#模板变量)。

## 添加订阅

在 **北向应用** 页面点击 MQTT V2 应用卡片，进入 **组列表** 页，点击 **添加订阅**：

- **南向设备**：选择要订阅的南向设备，例如 modbus-1。
- **组**：选择该设备下的组，例如 group-1。
- **主题**：该组的数据 topic，默认为 `${prefix}/${device}/data`，也就是设备数据 topic。
  - 可用变量：`${prefix}`（Topic 前缀）、`${app}`（北向应用名）、`${device}`（南向设备名）、`${group}`（组名）。
  - 不能包含 `+`、`#`，不能以 `$` 开头（`${` 除外），最长 255 个字符。
  - 使用变量时，修改前缀或名称后 topic 会自动更新。例如，要让每个组发布到单独的 topic，可以填 `${prefix}/${device}/${group}`。

同一设备的多个组共用该设备的状态和写请求 topic。默认情况下，各组的数据也发布到同一个数据 topic，可通过数据消息中的 `group` 字段区分。

## 运行与维护

在应用卡片或应用列表中，可以点击数据统计图表查看应用的运行情况，以及收发数据的统计。统计字段的说明见 [创建北向应用](../north-apps.md)。

如果运行出现问题，可以点击 DEBUG 日志图标，系统会打印该节点 DEBUG 级别的日志，十分钟后恢复为系统默认的日志级别。之后在 **系统信息** -> **日志** 中查看日志，进行故障诊断。
